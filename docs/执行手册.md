## 场景一：首次建库（全量）

拿到通达信导出的 zip 压缩包后，按以下顺序执行。

### 步骤 1 — 写入 K 线到 DuckDB

```bash
python main.py ingest --zip /path/to/hsjday-2026-05-21.zip
```

- 解析 zip 内所有 `.day` 二进制文件，写入 DuckDB `kline` 表
- 完成后自动创建 `.sync_state.json` 门控文件，后续步骤才能执行
- 输出：`ingest 完成: N 只股票`

### 步骤 2 — 采集当日信号数据

```bash
python main.py collect
# 可选：同时采集腾讯财经 PE/PB 快照
python main.py collect --with-tencent
```

- 更新北向资金快照 → DuckDB `northbound` 表
- 更新龙虎榜 → DuckDB `lhb` 表

### 步骤 3 — 拉取基本面缓存（约 1-2 小时）

```bash
# 正常拉取（有缓存时跳过）
python main.py fetch-fund

# 强制全量重拉
python main.py fetch-fund --refresh

# 调试：只拉 100 只
python main.py fetch-fund --sample 100 --delay 0.5
```

- 结果写入 `data/fundamentals/{code}.parquet`
- 覆盖不足 1000 只时 Phase 1 会警告，模型退化为纯技术因子

### 步骤 4 — 拉取资金流向缓存（**关 VPN 运行**）

```bash
# 关 VPN 后执行，避免东方财富 IP 封锁
python main.py fetch-flow

# 调试
python main.py fetch-flow --sample 100 --delay 0.5
```

- 结果写入 `data/fund_flow/`
- 失败 200 只自动熔断，已有缓存不受影响
- 当前覆盖率约 10%，缺失股票的 `north_net_*` 因子自动填 NaN

### 步骤 5 — Phase 1：特征工程

```bash
python main.py 1

# 调试：只处理 200 只股票
python main.py 1 --sample 200
```

- 合并 K 线 + 基本面 + 信号因子，输出 62 个特征
- 结果写入 DuckDB `features` 表
- 输出：`Phase 1 完成，N 行 × 62 列，时间范围 YYYY-MM-DD ~ YYYY-MM-DD`

### 步骤 6 — Phase 2：模型训练

```bash
# 推荐：滚动窗口（最近 2 年数据，最快）
python main.py 2 --rolling

# 含 Walk-Forward CV 诊断（更慢，用于评估时间稳定性）
python main.py 2 --walk-forward

# 滚动窗口 + 训练年数自定义
python main.py 2 --rolling --train-years 3

# 评估后用全量数据重训生产模型
python main.py 2 --rolling --final
```

- 训练 LightGBM 三分类 + Ridge 回归，按验证集 IC 加权集成
- 模型保存到 `data/models/`
- 输出评估指标：训练/验证/测试集 IC、准确率、F1

### 步骤 7 — Phase 3：组合回测

```bash
# 标准回测（Top-50，每 5 日调仓）
python main.py 3

# 自定义参数
python main.py 3 --top-k 30 --rebalance 3

# 散户模式（只换被淘汰股）
python main.py 3 --replace-only

# 高级参数
python main.py 3 --top-k 50 --max-weight 0.05 --max-sector-weight 0.40 --max-turnover 0.5
```

- 输出：回测报告、权益曲线图、交易明细
- 保存到 `data/backtest/`

## 场景二：日常增量更新（每个交易日）

**无需新 zip，通过 mootdx TCP 拉取增量数据。**

```bash
# 标准日更（2-3 分钟）
python main.py update

# 同时更新腾讯 PE/PB 快照
python main.py update --with-tencent

# 更新完后自动重训模型
python main.py update --retrain
```

执行顺序：mootdx 增量 K 线 → 北向资金快照 → [腾讯快照] → 增量特征组装 → [重训]

## 全参数速查

| 参数 | 适用命令 | 说明 |
|------|----------|------|
| `--zip <path>` | `ingest`, `sync` | zip 文件路径 |
| `--sample N` | 多数命令 | 调试用，只处理 N 只股票 |
| `--delay S` | `fetch-fund`, `fetch-flow` | 请求间隔秒数（默认 0.3）|
| `--refresh` | `fetch-fund` | 忽略缓存，强制重新拉取 |
| `--with-tencent` | `collect`, `update` | 同时采集腾讯财经快照 |
| `--rolling` | `2` | 滚动窗口训练（推荐）|
| `--walk-forward` | `2` | Walk-Forward CV 诊断 |
| `--train-years N` | `2` | 滚动窗口年数（默认 2）|
| `--final` | `2` | 评估后用全量数据重训 |
| `--top-k N` | `3`, `scan` | 持仓数量（默认 50）|
| `--rebalance N` | `3` | 调仓间隔交易日数（默认 5）|
| `--replace-only` | `3`, `scan` | 散户模式，不做存量再平衡 |
| `--max-weight F` | `3` | 单股最大权重（默认 0.05）|
| `--max-sector-weight F` | `3` | 板块最大权重（默认 0.40）|
| `--max-turnover F` | `3` | 单次最大换手率（默认 0.5）|
| `--retrain` | `update` | 增量更新后触发重训 |
| `--equal-weight` | `3` | 等权替代信号加权 |

## 常见问题

| 现象 | 原因 | 解决 |
|------|------|------|
| `未找到数据同步确认记录` | 未运行 `ingest` 或 `sync` | 先执行 `ingest --zip` |
| `DuckDB kline 表和 data/raw/kline/ 均无数据` | 数据库未初始化 | `ingest --zip <path>` |
| `基本面缓存仅 N 只，模型将退化` | `fetch-fund` 未完成 | 运行 `fetch-fund`（约 1-2 小时）|
| `RemoteDisconnected` 资金流向失败 | 开着 VPN | 关 VPN 后重跑 `fetch-flow` |
| `collect --refresh` 后水位未更新 | watermark.json 需手动修正 | 编辑 `data/watermark.json` 的日期字段 |
| `ingest` 解压后路径混乱 | Windows zip 反斜杠 | 已在代码中修复（2026-05-19）|
