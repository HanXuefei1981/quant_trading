# 2026-05-19 开发日志

## [1] 修复 sync 命令在 macOS 解压 Windows zip 路径 bug

**类型**: fix
**影响范围**: `main.py`（`sync` 函数解压逻辑）
**关联**: [2026-05-18 #1] 资金流向脚本；每次 sync 新数据包均受影响

### 问题 / 动机

通达信导出的 zip 使用 Windows 反斜杠路径（如 `sh\lday\sh000001.day`）。
Python `zipfile.extractall()` 在 macOS 上不自动转换路径分隔符，导致：
- 文件被解压为带字面量反斜杠的文件名（`/tdx_data/sh\lday\sh000001.day`）
- 原有正确路径下的 TDX 二进制文件**未被覆盖**
- `get_max_trading_date()` 读到的仍是旧数据（2026-05-11），sync 日期核对失败

该 bug 此前一直潜伏，因为历史上使用的 zip 恰好与已有数据日期相同，今天首次用新数据包暴露。

### 变更内容

将 `zipfile.extractall()` 改为逐成员处理，提取前将 `\` 替换为 `/`：

```python
with zipfile.ZipFile(str(zip_path), "r") as zf:
    for member in zf.infolist():
        normalized = Path(member.filename.replace("\\", "/"))
        dest = TDX_VIPDOC_DIR / normalized
        if member.is_dir():
            dest.mkdir(parents=True, exist_ok=True)
        else:
            dest.parent.mkdir(parents=True, exist_ok=True)
            dest.write_bytes(zf.read(member.filename))
```

同次提交还包含之前 session 积累但未提交的功能：`collect`、`fetch-flow`、`update` 命令及 Phase 2 扩展参数（`--rolling`、`--walk-forward`、`--final`、`--retrain` 等）。

**提交**：`adc650c`

### 验证方式

- 修复后重新运行 `sync --zip hsjday-2026-05-19.zip`，核对结果从"✗ 不匹配"变为"✓ 匹配"
- `get_max_trading_date()` 正确返回 `2026-05-18`
- 抽查 `sh000001.day`：总记录数从 8636 增至 8641，最后一条日期 `20260518`
