## [1] 实现 sync 命令：通达信数据同步与确认门控

**类型**: feat
**影响范围**: `main.py`, `src/data/tdx_reader.py`, `data/.sync_state.json`（新增）
**关联**: 承接 [2026-05-07 #1]，建立数据同步的可信流程

### 问题 / 动机

每次更新通达信全量数据时缺乏：
1. **日期一致性核对**：压缩包文件名声明的日期是否与实际数据吻合
2. **人工确认**：避免错误数据被默认接受，污染下游训练
3. **阶段门控**：phase1 之前必须有显式确认记录

四项需求：
1. 解压后根据文件名日期 -1 解析期望数据截止日期
2. 实际最大交易日 vs 期望日期核对
3. 每次数据采用**全量更新**（暂不增量）
4. 没有用户确认不能运行后续阶段

### 变更内容

**新增 `main.py::sync()`**
- 从压缩包文件名解析日期：`hsjday-2026-05-12.zip` → 期望截止 2026-05-11（-1 天）
- 解压到 `TDX_VIPDOC_DIR`
- 调用新增的 `get_max_trading_date()` 读实际最新交易日
- 打印对比结果，要求 `input("...y/N")` 显式确认
- 确认通过后写入 `data/.sync_state.json`

**新增 `src/data/tdx_reader.py::get_max_trading_date()`**
- 扫描所有 `.day` 文件的最后 32 字节
- 解析 `date_int`，返回全市场最大日期
- 不需要读完整文件，扫描快速

**phase1 入口门控**
- 检查 `_SYNC_STATE_FILE` 存在性，缺失则报错退出
- 强制 `use_cache=False`（全量更新需求）

**新增 CLI 参数**
- `python main.py sync --zip /path/to/hsjday-YYYY-MM-DD.zip`

### 验证方式

- 用 2026-05-12 压缩包跑 sync，正确解析期望日期 2026-05-11
- 实际扫描结果与期望一致，确认后 `.sync_state.json` 写入正确
- phase1 在无 sync state 时正确拒绝执行

### 待跟进

- [x] 之后所有 phase1 必须先 sync
- [ ] 考虑增量更新模式（当前每次全量）

## [2] 引入 ST / 科创板交易权限过滤

**类型**: feat
**影响范围**: `src/data/stock_filter.py`（新增）, `src/backtest/engine.py`, `config/settings.py`, `main.py`

### 问题 / 动机

账户交易权限限制：
1. **ST / *ST 股票**：账户未开通风险警示交易权限
2. **科创板**（688xxx）：账户未开通科创板交易权限
3. **新股**（上市不足 3 个月）：已被 `MIN_TRADE_DAYS=250` 覆盖

之前的 `filter_valid_stocks` ST 检查依赖股票名称，但 TDX 本地数据没有股票名（只有代码），所以 ST 过滤实际未生效。

### 变更内容

**新增 `src/data/stock_filter.py::get_st_codes()`**
- 调用 akshare `stock_info_a_code_name()` 拉全市场名称
- 用正则 `r"\bST\b|^\*?ST"` 匹配 ST / *ST 股票
- 缓存到 `data/processed/st_codes.json`，有效期 `ST_CACHE_DAYS=7` 天
- akshare 失败时返回空集合并警告（不阻塞主流程）

**修改 `src/backtest/engine.py::_is_stock()`**
- 增加科创板判断：`if EXCLUDE_KCYB and code.startswith("688"): return False`

**修改 `generate_signals()` 签名**
- 新增 `exclude_codes: Optional[set]` 参数
- 应用 `stock_mask &= ~df["code"].isin(exclude_codes)`

**新增配置项 `config/settings.py`**
- `EXCLUDE_KCYB = True`
- `ST_CACHE_DAYS = 7`

**修改 phase3 / scan 主流程**
- 调用 `get_st_codes()` 后将其作为 `exclude_codes` 传给 `generate_signals`

### 验证方式

- 跑 scan 命令，日志输出"已过滤 ST 等不可交易股票，排除 N 只"
- 检查输出 Top-10 中无 688xxx 股票
- ST 列表缓存正确生成 `st_codes.json`

### 待跟进

- [x] 此次完整覆盖三大权限限制
- [ ] 北交所（8xxxxx）权限是否也需要类似处理？当前未单独过滤

## [3] 新增推断模式：scan 用最新无标签数据生成信号

**类型**: feat
**影响范围**: `src/data/pipeline.py`, `main.py`

### 问题 / 动机

`market_features.parquet` 由于 `shift(-5)` 标签的需求，最新数据点永远比 TDX 数据落后 5 个交易日。
具体例子：TDX 数据到 2026-05-11，但 `market_features.parquet` 最新只有 2026-05-04。

scan 命令的目的是给散户输出"最新可建仓信号"，应当用最新截面，而不是 5 天前的。

### 变更内容

**新增 `src/data/pipeline.py::load_inference_data()`**
- 直接读个股缓存 `PROCESSED_DIR/{code}.parquet`（不读合并后的 market_features）
- 取每只股票的最后一行（可能含 `future_ret=NaN`，但有完整特征）
- 过滤到 `combined["date"] == latest_date`（停牌股自动排除）
- 应用 `preprocess_features` 做截面 MAD → 中性化 → Z-score

**修改 `scan()` 主流程**
- 用 `load_inference_data()` 替代 `load_processed_data()`
- 扫描日期为 TDX 最新交易日（2026-05-11），而非 market_features 最新

### 验证方式

- 跑 scan，日志输出"推断截面日期: 2026-05-11，共 N 只股票"
- 输出与之前的 2026-04-28 截面对比，特征值不同（说明确实是新截面）
- 耗时约 54 秒，远快于完整 phase1 重跑

### 待跟进

- [x] scan 可用最新数据
- [ ] 是否需要给 phase3 也提供类似的"最新 K 天滚动预测"模式
