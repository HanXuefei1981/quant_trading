# 开发日志（Dev Log）

按日期记录量化交易系统的每次修改、迭代、问题排查与决策过程。

## 用途

- **回顾**：某次变更的动机、过程、结果
- **追溯**：某个功能/Bug 的引入时间和上下文
- **测试方案**：基于变更点输出回归测试清单
- **决策档案**：技术选型与方案对比的依据

## 目录结构

```
docs/dev-log/
├── README.md              # 本文件（索引）
├── _template.md           # 单日日志模板
├── YYYY-MM-DD.md          # 按日记录（一天一个文件）
└── ...
```

## 文件命名约定

- 一天一个文件：`2026-05-13.md`
- 一天多个变更在同一文件内用 `## [N]` 编号分节
- 跨日的长任务（如全量数据拉取）记录在启动当天，在完成当天追加链接

## 单条变更必备字段

| 字段 | 说明 |
|------|------|
| **类型** | `feat` / `fix` / `refactor` / `docs` / `chore` / `perf` / `data` |
| **影响范围** | 涉及的文件/模块清单 |
| **问题/动机** | 为什么做这次变更 |
| **变更内容** | 关键改动点（不必逐行罗列） |
| **验证方式** | 跑了哪些测试、看到什么结果 |
| **待跟进** | 后续需要做什么（迁移到 task 或新条目） |
