## 一、背景与优化目标

### 现状诊断

通过对现有代码库的审查，识别出以下核心痛点：

```
pipeline.py: 读TDX + merge基本面 + merge资金流向 + 特征工程 → 全耦合在一个函数里
每次 phase1 = 重跑全部5641只 × 全部历史 ≈ 25分钟
新增一个数据源 = 必须改 pipeline.py 核心函数
数据存在哪/格式是什么 = 分散在多处，没有统一约定
```

### 三大优化目标

**目标一：数据采集层与业务层解耦**  
数据采集层输出标准接口数据（标准化 parquet），业务层（模型层）直接读取，不调用任何数据接口。

**目标二：历史全量 + 增量修复**  
通达信近5年全量数据已有，后续采用水位机制实现增量更新，将每日 phase1 运行时间从 25 分钟压缩到 2-3 分钟。覆盖技术因子、基本面因子、资金流向因子。

**目标三：新因子扩展**  
在稳定架构上增加基本面（研报+EPS共识）因子和信号（北向+龙虎榜）因子。暂不引入新闻情感等高成本低收益的 NLP 类因子。

### 标准接口定义（BaseCollector）

```python
# src/collectors/base.py
class BaseCollector(ABC):
    DATA_TYPE: str      # "kline" / "tencent" / "fundamentals" / ...

    def fetch_one(self, code: str, since: date = None) -> pd.DataFrame | None:
        """拉取单股数据，返回 (date, code, ...) 结构 DataFrame；since=增量起点"""

    def fetch_all(self, codes: list[str], incremental: bool = True) -> CollectStats:
        """批量拉取，内部读水位决定 since，返回 {ok, cached, fail, skipped}"""

    def load(self, code: str) -> pd.DataFrame | None:
        """从本地缓存加载（不触发网络请求）"""

    def load_market(self) -> pd.DataFrame | None:
        """加载全市场宽表（northbound / 行业等共享数据专用）"""
```

所有 collector 输出格式统一：`date(datetime64) + code(str) + 业务列`，按日期升序，无重复行。

### 水位机制（Watermark）

```json
// data/watermark.json（自动维护，不手动编辑）
{
  "kline":        "2026-05-14",
  "tencent":      "2026-05-14",
  "fundamentals": "2026-05-10",
  "fund_flow":    "2026-05-14",
  "northbound":   "2026-05-14",
  "features":     "2026-05-14"
}
```

### 增量特征计算流程

```
增量 phase1（每日 update 命令）：
  1. 读 watermark["features"] = T（上次特征计算日期）
  2. 对每只股票：
     a. 读 data/raw/kline/{code}.parquet 中 (T - 300天) 以后的数据
        （300天 = max滚动窗口252 + 安全边际，确保滚动指标计算正确）
     b. merge 各 raw 数据源的增量部分
     c. 计算特征，只保留 date > T 的新行
     d. append 到 data/processed/{code}.parquet（不重写历史）
  3. 跨截面步骤：只对 date > T 的日期做标签 + 归一化
  4. append 到 market_features.parquet
  5. 更新 watermark["features"] = 今日
```

## 三、里程碑与执行计划

**工期：3天 | 风险：低（不改模型，只重构数据层）**

**工期：5-7天 | 依赖：M2 完成 | 前提：验证基准模型 IC**

| 因子组 | 数据来源 | 具体因子 | 更新频率 | 注意事项 |

#### 第二批：中风险，需验证 IC 后决策

| 因子组 | 数据来源 | 具体因子 | 风险点 |
|--------|---------|---------|--------|
| 公告信号 | 巨潮 cninfo | `days_since_earnings`，`earnings_surprise` | 业绩预告需规则提取，开发复杂度高 |

#### 暂不纳入

- 新闻情感分析（5641只 × 日均新闻推理成本过高）
- 公告全文 NLP（等模型稳定后单独评估）

**新因子验收标准：**
- 每个新因子 IC 绝对值 > 0.02
- 方向与业务逻辑一致（机构覆盖↑ → 正向，龙虎榜净买↑ → 正向）
- 加入新因子后模型 IC 相比基准提升 ≥ 5%

## 七、决策记录

1. **不引入新闻情感因子**：5641只股票每日推理成本过高，等基础模型稳定后单独评估
2. **北向数据源从 eastmoney 切换 THS**：eastmoney 自2024-08起净买额字段断供，THS hsgtApi 实测稳定（262个时间点，零鉴权）
3. **M3 先做第一批因子，IC验证后再决定第二批**：避免盲目堆因子掩盖模型基础问题
4. **个股资金流向暂缓**：东方财富接口限频严重（100次连续失败即终止），百度接口盘中待验证，不阻塞 M1/M2 进度
